The Problem No One Has Formally Named — Until Now

Every production ML team running anomaly detection, regime change detection, or early-warning systems uses the same evaluation pipeline: compute AUROC, check F1, ship the model.

There is a structural flaw baked into this process that has persisted unaddressed for decades.

The Core Issue

Standard metrics are temporally agnostic. They assign identical credit to a detection that fires at t* + 1 and a detection that fires at t* + 100. Two detectors with identical AUROC scores can have radically different operational behavior—one saving the system, one watching it fail.

The HED Score was built to close this gap. It is the first evaluation metric with a time parameter.

Why AUC Collapses in Production

The Area Under the ROC Curve is defined as:

$$\text{AUC} = \int_0^1 \text{TPR}(t) \, d(\text{FPR}(t))$$

This integral aggregates classifier performance across all decision thresholds. It is a powerful measure of ranking quality—how well a model separates positive from negative cases over a static sample.

The structural limitation: AUC is defined over a label set $\{y_i, \hat{p}_i\}_{i=1}^{N}$ where the index $i$ carries no temporal semantics. The computation treats $i=1$ and $i=N$ as exchangeable. Formally, for any permutation $\sigma$ of the index set:

$$\text{AUC}(\{y_i, \hat{p}_i\}) = \text{AUC}(\{y_{\sigma(i)}, \hat{p}_{\sigma(i)}\})$$

This means AUC is invariant to the temporal ordering of predictions. In a system where the cost of latency is operationally catastrophic, this is not a limitation. It is a disqualification.

The HED Framework: Mathematical Formulation

Discrete Formulation

For a discrete probability stream $P = \{P(t)\}_{t=0}^{T-1}$, a known onset $t^*$, and decay constant $\lambda > 0$:

$$\boxed{\text{HED}(P,\, t^*,\, \lambda) = \sum_{t=t^*}^{T-1} \bigl(P(t) - B\bigr) \cdot \exp\!\bigl(-\lambda\,(t - t^*)\bigr)}$$

Components

  • P(t) — Posterior probability of the anomalous regime at timestep t
  • t* — True onset timestep of the regime shift (change point)
  • B — Baseline correction: $B = \frac{1}{t^*} \sum_{t=0}^{t^*-1} P(t)$ (prevents false-alarm inflation)
  • λ — Hiremath Decay Constant (domain-specific latency tolerance)

The Hiremath Decay Constant λ

The decay constant $\lambda$ encodes domain-specific latency tolerance. It governs how aggressively late detections are penalized:

$$w(t) = \exp\!\bigl(-\lambda\,(t - t^*)\bigr)$$

Axiomatic Foundations

The HED Score satisfies three formally proved axioms. These are not design aspirations—they are mathematical guarantees proved in the accompanying paper.

A1 — Temporal Monotonicity

Guarantee: Detecting earlier is always rewarded. There is no parameter configuration under which a delayed detection scores higher than an earlier detection of equivalent quality.

$$\text{HED}(P_a, t^*, \lambda) > \text{HED}(P_b, t^*, \lambda) \quad \forall\, \lambda > 0$$

Why classic metrics collapse here: AUC is invariant to temporal ordering by construction. A metric that satisfies temporal monotonicity cannot be AUC-equivalent. The axioms are mutually exclusive.

A2 — Invariance to Pre-Attack Bias

Guarantee: The score is completely insensitive to the detector's systematic false-alarm rate before the regime shift.

$$\text{HED}(P_a, t^*, \lambda) = \text{HED}(P_b, t^*, \lambda)$$

Operational significance: This prevents adversarial evaluation gaming where a model achieves high early-detection scores simply by maintaining permanently elevated output. HED measures genuine post-onset response, not pre-event noise.

A3 — Sensitivity Decomposability

Guarantee: Individual failure modes are diagnosable. A low HED score reveals whether the model is failing on detection confidence, detection timing, or pre-event calibration.

Why this matters: A single scalar metric that cannot be decomposed is an oracle, not a diagnostic tool. A3 makes HED a diagnostic instrument for targeted architectural improvements.

Production Example: Comparing the Three Detectors

# Import and create synthetic detectors from hed import hed_score from hed.metrics import auc_score import numpy as np # Create three canonical detector paradigms n_steps = 300 onset = 100 lam = 0.10 # Ground truth labels = np.zeros(n_steps) labels[onset:] = 1 # Detector 1: Immediate Jump immediate = np.zeros(n_steps) immediate[onset:] = np.linspace(0, 0.90, n_steps - onset) ** 0.1 # Detector 2: Linear Ramp ramp = np.zeros(n_steps) ramp[onset:] = np.linspace(0, 0.90, n_steps - onset) # Detector 3: Step-Delayed delayed = np.zeros(n_steps) delayed[onset + 40:] = 0.90 # Evaluate detectors = { "Immediate Jump": immediate, "Linear Ramp": ramp, "Step-Delayed": delayed, } for name, prob in detectors.items(): hed = hed_score(prob, t_star=onset, lam=lam) auc = auc_score(prob, labels) print(f"{name:20} AUROC={auc:.3f} HED={hed:.3f}")

Key Concepts

What HED Is Not

HED does not replace AUROC. This is important enough to state explicitly.

Metric Measures When to Use
AUROC Ranking quality across thresholds Evaluating classification separability
F1 / Precision-Recall Performance at a fixed threshold Evaluating at a chosen operating point
HED Temporal quality: how early, how confidently Any system where detection latency has consequences

Report both AUROC and HED. They answer different questions. A system evaluated on only one gives you half the picture.

Research Ecosystem

The HED Score is the foundation of a broader temporal evaluation ecosystem. Development includes:

  • Core metric: Stable, tested, production-ready via PyPI
  • Benchmark suite: NSL-KDD, UNSW-NB15, CICIDS, synthetic regimes
